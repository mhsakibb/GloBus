\chapter{SYSTEM TESTING}
\section{Introduction to Testing}
Testing is the process in which the system is run using manually created or automated inputs to verify whether the system is working correctly as desired. During systems testing, the GloBus platform is used experimentally to ensure that the software does not fail under expected or unexpected loads. In other words, we verify that it runs according to its specifications and provides a seamless shopping experience for the users. Special test data are input for processing, and the results are examined to locate bugs before deployment.

Testing of a system is generally done in two phases: Unit Testing, which is performed for each module (e.g., Cart, Checkout, Authentication) independently upon its completion, and System Testing, which is performed on the integrated system at the end of the development lifecycle.

\section{Validation Criteria}
The validation criteria for the GloBus e-commerce platform are as follows:
\begin{itemize}
    \item Form inputs (e.g., Registration, Checkout details) are rigorously validated on the frontend (React) before being sent, and re-validated on the backend (Node.js) before storing them in MongoDB.
    \item All screens maintain a consistent UI/UX. They follow a strict Tailwind CSS utility class structure, maintaining consistent color palettes across both Dark and Light modes.
    \item Unique constraints (e.g., Email addresses during registration) cannot be duplicated in the database.
    \item Payment validation must strictly await server-side IPN (Instant Payment Notification) from SSLCommerz before fulfilling an order.
\end{itemize}

\section{Types of Testing Performed}

\subsection{Functional Testing}
Functional testing is executed to ensure that every feature of the platform works as intended. For GloBus, this meant verifying that users can successfully register, search for products using text or AI Vision, add items to the cart, and securely check out.

\subsection{Unit Testing}
Unit testing focuses on testing individual components in isolation. For our frontend, this meant testing individual React components (like the `AddToCartButton` or `Timer`). On the backend, controllers (like `productController.js` and `paymentController.js`) were tested in isolation to ensure data is fetched and manipulated correctly without running the entire server infrastructure.

\subsection{Integration Testing}
Integration testing verifies that different modules work together correctly. The main purpose was to ensure that the interface between the frontend (React/Vite) and the backend REST API (Express) functions perfectly. A critical integration test involved ensuring the Shopping Cart data synchronizes flawlessly with the database upon user login.

\section{Test Data Used}
The proper selection of data is very important. If the test data is not representative of real-world scenarios, the reliability of the system is questionable.
\begin{itemize}
    \item \textbf{Using Live Test Data:} Live tests were conducted using real sandbox credentials for the SSLCommerz payment gateway to simulate actual financial transactions without risking real money.
    \item \textbf{Using Artificial Test Data:} Artificial data (dummy products, fake user accounts) were generated using our database seed script (`seedOrders.js`) to test how the UI handles large volumes of products and pagination.
\end{itemize}

\section{Testing Summary}
We tested all the panels assigned for Users and Administrators. The project was tested locally and in the staging environment with all possible interaction flows. The testing involved using generated dummy records via `seedOrders.js` to populate the database and checking whether the frontend accurately reflects the backend state.

The testing process involved:
\begin{itemize}
    \item Testing for successful and failed login processes.
    \item Testing for form validation across Checkout and Contact pages.
    \item Testing the accuracy of the AI Vision image processing.
    \item Testing real-time Cart state management.
    \item Testing the SSLCommerz payment pipeline and order generation.
    \item Testing Admin CRUD operations on products and users.
\end{itemize}

The project was successfully tested, and several minor bugs related to responsive design on smaller screens and cart synchronization were fixed. The final system operates smoothly without any critical failures.
